# Status update 1 (16.10.2026)

**Period:** 06.10.2026 to 16.10.2026

## Done

- Architecture design of the pipeline and the evaluation: [architecture-design.md](../architecture/architecture-design.md). Classical algorithms make every decision first and attach a confidence score. The local LLM (Ollama) is called only for low-confidence decisions and for tasks heuristics cannot do, such as figure descriptions and table repair.
- Five diagrams in [docs/architecture/diagrams](../architecture/diagrams):
  - [01 Components](../architecture/diagrams/01-components.svg): the pipeline package, the RAG prototype and the evaluation harness, with their external tools
  - [02 Document model](../architecture/diagrams/02-class-document-model.svg): the data structure that every stage reads and writes
  - [03 Pipeline](../architecture/diagrams/03-class-pipeline.svg): stages, configuration and the LLM layer
  - [04 Pipeline activity](../architecture/diagrams/04-activity-pipeline.svg): one run, including where low confidence turns into an LLM request
  - [05 LLM request states](../architecture/diagrams/05-state-llm-request.svg): what happens to a request when the answer is valid or invalid, or when the LLM is switched off
- Python package skeleton (`hybrid-pdf-extraction` on PyPI later, import name `hybrid_pdf`), built with uv, with pytest and ruff set up.

## Results

No measurements yet. The evaluation code (corpus download, ground truth from LaTeX sources, metrics, first baselines) is step 2 of the development order in section 10 of the design.

## Decisions

- D-001: three document categories, CS as the target category plus Medical and Physics (provisional)
- D-002: ground truth generated from the publishers' sources (arXiv LaTeX, PubMed Central JATS XML), with a small sample checked by hand
- D-003: classical algorithms first, the LLM only on low confidence, and an ensemble of extractors for tables
- D-004: license changed from MIT to AGPL-3.0-or-later, because PyMuPDF is AGPL licensed

All four are proposals that I would like to discuss at the meeting on 29.10.2026. Details and the rejected alternatives are in [DECISIONS.md](../../DECISIONS.md).

## Problems and changes of plan

- The repo started under the MIT license. Depending on PyMuPDF makes AGPL the honest license for the package, so it was changed (D-004).
- The number of document categories is not fixed yet (D-001).

## Next steps

- Finish step 1 by the meeting on 29.10.2026: document model, pipeline runner, PDF ingest with PyMuPDF, Markdown and JSON export, and the `hybrid-pdf extract` command, demonstrated on a real arXiv paper.
- Then step 2: corpus manifest and downloader, ground-truth builder for arXiv LaTeX, first metrics and two baselines, which give the first end-to-end numbers.
